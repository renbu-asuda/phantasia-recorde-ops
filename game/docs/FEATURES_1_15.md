# PRO 1.15.0 — 創作と運用の拡張

PRO 1.14.2までのパック・セーブを読み込めます。新機能を使うデータの出力は Unit 9 / Mission 5 / Item 7 / Bundle 9 です。新形式は旧本体に読み込ませないでください。ゲームは従来どおりブラウザだけで動き、Nodeやサーバーを用意する必要はありません。

「拡張パック」から **PRO 1.15 新機能デモ** を追加できます。メーカーには `samples/pro_115_feature_sample.js` を読み込んでください。既存のキャラクターや拡張パックを自動的に改変する機能ではありません。

## 6. 複合スキル

統合メーカーの「スキル」で、条件を「すべて」「どれか」で組み合わせ、効果を最大8個指定できます。条件の入れ子はデータでは4段まで対応します。画面では一段の組合せを作成でき、既存の入れ子は保持・表示できます。

```js
{
  id: 'awaken', name: '覚醒', trigger: 'turn_start', chance: 100, maxUses: 1,
  cond: { all: [{type:'turn_ge',value:3},{type:'hp_below',value:50}] },
  effects: [
    {effect:'atk_up_pct',value:30,duration:3,target:'self'},
    {effect:'mob_up_pct',value:20,duration:3,target:'self'},
    {effect:'heal_flat',value:500,target:'self'}
  ]
}
```

発動率と使用回数はスキル全体で一度判定・消費し、効果を記載順に処理します。効果を個別のスキルとして抽選しません。何も適用されなければ使用回数を返します。効果配列がある場合は、従来の単独 `effect/value` は実行されません。発動タイミングと効果の組合せは従来の対応表に従い、非対応の組合せは検証エラーになります。

## 7. 段階変化・変形

ユニットの「拡張」に `phases` を追加できます。最大16段階、各IDは一戦闘に一度。条件はHP・TURN・生存体数です。該当する最初の未使用段階をチェック時点ごとに一つ適用します。

- `stats`: 変化後の絶対値。省略した能力は現在値を維持。DEFなどは明示の0にも変更できます。最大HPは1以上。
- `hpMode`: `ratio`（割合維持）、`keep`（現在値維持）、`value`（`hpValue`を指定）。
- `weaponIds` / `skillIds`: 同一パックの共有データを選択。省略は維持。`skillIds: []` はスキルなし。
- `weapons` / `skills`: 単独パックでの埋め込みにも対応。
- `ai`: 変化後の狙い方。`lines`: 変化時の会話。

戦闘中だけの変更です。戦闘後のHPは、変化前の最大HPに対する割合へ戻して保存します。変形後の能力や武装が恒久強化として残ることはありません。武装切替時は武装使用回数・待ちTURNをリセットし、スキル使用回数はIDごとに維持します。

## 8. 作戦イベント・選択・分岐

作戦の「勝敗条件・ウェーブ」で設定します。

- `events`: 最大32件。`when` は `turn` / `wave` / `boss_hp` / `unit_down`。各ID一度だけ発生。
- `value`: TURN、波番号（最初が1）、ボスHP%。撃破条件には `unitId`。
- `requiredUnitId`: 指定ユニットが味方として参加しているときだけ発生。雇用した複製も元ユニットIDで判定。
- `lines` は会話、`terrain` は変更先の地形名、`flags` は保存される分岐フラグ。
- `story.defeat`: 敗北後の会話。`story.choices`: 作戦前の選択肢（最大8件、`text/flags/lines`）。選択はスキップ不可。
- `resultFlags.win/lose/draw`: 戦闘結果別のフラグ。
- `requires.flags`: 出撃に必要なフラグ値。フラグは安全なIDとtrue/falseで指定。未設定はfalseです。

イベントのフラグは戦闘結果にかかわらず保存します。勝利だけで立てたいフラグは `resultFlags.win` を使ってください。会話や選択の途中で処理エラーが起きた場合、結果確定前なら出撃前の状態へ戻ります。

## 9. 解放条件・入手経路

統合メーカー「パック・出力 → 関係図と到達条件を確認」、ゲームのデータ管理「解放条件・入手経路を見る」で、作戦・素材・研究・加入・雇用をつないだ関係を一覧表示します。対象で絞り込めます。

外部参照、循環候補、パック内では到達を確認できない作戦・研究を表示します。条件の循環でも別の入手経路があれば成立するため、警告だけで出力を禁止しません。曜日・資金・戦闘難度などを含めた完全な攻略可能性の証明ではありません。

## 10. 共有データの影響

共有スキル・武装の編集画面下に使用先を表示します。ユニット本体、装備、ツリー、パイロット、変形後の参照も検出します。

- 使用先のボタンで編集画面へ移動。
- 編集開始時との数値・設定差を表示。
- 「複製してこのデータだけ変更」で共有データを複製し、選んだ使用元だけを新IDに接続。

一つの使用元の中にある同じ参照はまとめて専用化します。例えば一ユニット内の本体と変形後が同じ武装IDを使っていれば、両方をそのユニット専用のコピーへ接続します。使用中データの削除も防止します。

## 11. 編集履歴・保存時点・一括変更

統合メーカーの「パック・出力」にUndo/Redoを追加。短い連続入力はまとめ、最大40状態をセッション内で保持します。ページ再読込後はUndo履歴を持ち越しません。

名前付き保存はブラウザに直近3件保持し、ページを開き直しても復元可能です。容量不足は表示し、保存できたと偽りません。JSの書出しも従来どおり利用できます。

ユニット・作戦・アイテムの一覧下で対象を選び、タグを一括追加できます。ユニットはHP/ATK/DEF/MOB/ACCの倍率変更も可能。変更件数と差分を確認してから適用します。データ取込にも変更前後の差分確認を追加しています。

## 12. パックの情報・更新・復元

統合パックに `author`、`packVersion`、`dependencies`（必要な他パックID）を指定できます。パック版番号は表示用で、依存先の最低版番号指定ではありません。

ゲームへの取込で追加・変更・削除と変更フィールド、他パックとのID競合、使用中ユニット・装備の削除、依存不足を確認します。依存先が同時に読み込まれる場合も認めます。必要なパックが不足していれば取込を止めます。

統合パック適用前に進行状況と追加パックを一件バックアップし、データ管理から「直前のパック更新前へ戻す」で復元します。進行状況もその時点へ戻ります。バックアップ保存に失敗した場合は更新を開始しません。解除や個別形式の取込を一括で巻き戻す仕組みではありません。

## 13. 出撃収支・素材案内

出撃前に勝利時の基本収支を表示。現在の編成・育成・装備・疲労・HPで100回、seed 17の試算を行い、勝敗別回収資金、出撃費用、全修理費の概算から期待収支を表示します。星・実績・素材売却額は試算に含めません。

戦闘後には実際の資金増減と、全修理した場合の収支を表示します。修理費は見積りで、結果表示時に自動で支払いません。

研究画面で素材を選ぶと、入手作戦、ドロップ率、成功一回の期待入手数、研究に必要な不足数を表示。期待値は入手の保証ではありません。

## 14. 戦闘履歴・リプレイ

記録画面に直近10戦を保存し、選択した戦闘を当時のHP・隊列・ログとともに確認できます。前後移動、再生・停止、スライダー、TURN・変形・イベント等への移動、JSON書出し・読込に対応。再生は保存イベントの表示で、報酬や成長を再実行しません。メーカーの一回テスト戦闘にも同じビューを追加。

記録上限は4000イベント、一戦闘約40万文字、履歴合計約150万文字。長い戦闘は一部省略し、その旨を表示します。ブラウザの保存容量によってはセーブの書出しが必要です。

## 開発者向け検証

```sh
npm ci
npm test
npm run test:dom
npx playwright install chromium
npm run test:browser
```

ブラウザテストは390×844の表示幅で、デモの取込、編集、Undo/Redo、名前付き保存、専用化、実戦、分岐保存、履歴表示を検証します。既存ゲームの利用にnpmは不要です。
